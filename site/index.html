How it works

The real game. A small plugin inside the Steam version of The Battle of Polytopia exposes the game state and every legal action over a local API. The game itself decides what is legal, how battles go and who wins; nothing is simulated.

The setup. Perfection mode (highest score after 30 turns), Small 14×14 Lakes map, against 2 Hard CPU tribes. The model picks one of the four core tribes after reading the game's own descriptions; the CPUs are drawn from the other three.

Each turn. A fresh model session gets the rules, the current state (fog of war respected), the legal actions as tools, and a note of up to 400 words it wrote to itself last turn. That note is its only memory. Every model runs at medium reasoning effort.

The score. A model's share of all three players' final points, averaged over its 3 games. If the model is eliminated, the game ends there and the share uses the scores at that moment. Three games per model is a small sample, and maps vary, so treat close rankings as ties.

Why Polytopia? It rewards investing early (techs, cities, roads) over grabbing points now, which makes it a test of long-term judgment, and a 30-turn game is short enough to run on a subscription.

Reproduce it. Code, prompts and a setup guide are on GitHub (MIT). You need your own copy of the game; none of the game's files or text are included. The maps on this page are drawn from the game logs, not taken from the game.
